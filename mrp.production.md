# Manufacturing Order — `mrp.production`

**Ordenação padrão:** `priority desc, date_start asc,id`

---

## Campos Obrigatórios

- `product_id` **(many2one)** — Product ⚠️ obrigatório → `product.product`
- `product_qty` **(float)** — Quantity To Produce ⚠️ obrigatório
- `product_uom_id` **(many2one)** — Unit ⚠️ obrigatório → `uom.uom`
- `picking_type_id` **(many2one)** — Operation Type ⚠️ obrigatório → `stock.picking.type`
- `location_src_id` **(many2one)** — Components Location ⚠️ obrigatório → `stock.location`
  > Location where the system will look for components.
- `location_dest_id` **(many2one)** — Finished Products Location ⚠️ obrigatório → `stock.location`
  > Location where the system will stock the finished products.
- `date_start` **(datetime)** — Start ⚠️ obrigatório
  > Date you plan to start production or date you actually started production.
- `company_id` **(many2one)** — Company ⚠️ obrigatório → `res.company`
- `consumption` **(selection)** — Consumption ⚠️ obrigatório 🔒 readonly
  > Opções: `flexible` (Allowed), `warning` (Allowed with warning), `strict` (Blocked)

## Campos Principais

- `id` **(integer)** — ID 🔒 readonly
- `name` **(char)** — Reference 🔒 readonly
- `priority` **(selection)** — Priority
  > Components will be reserved first for the MO with the highest priorities.
  > Opções: `0` (Normal), `1` (Urgent)
- `backorder_sequence` **(integer)** — Backorder Sequence
  > Backorder sequence, if equals to 0 means there is not related backorder
- `origin` **(char)** — Source
  > Reference of the document that generated this production order request.
- `qty_producing` **(float)** — Quantity Producing
- `product_uom_qty` **(float)** — Total Quantity 🔒 readonly
- `date_deadline` **(datetime)** — Deadline
  > Informative date allowing to define when the manufacturing order should be processed at the latest to fulfill delivery on time.
- `date_finished` **(datetime)** — End 🔒 readonly
  > Date you expect to finish production or actual date you finished production.
- `state` **(selection)** — State 🔒 readonly
  >  * Draft: The MO is not confirmed yet.  * Confirmed: The MO is confirmed, the stock rules and the reordering of the components are trigerred.  * In Progress: The production has started (on the MO or on the WO).  * To Close: The production is done, the MO has to be closed.  * Done: The MO is closed, the stock moves are posted.   * Cancelled: The MO has been cancelled, can't be confirmed anymore.
  > Opções: `draft` (Draft), `confirmed` (Confirmed), `progress` (In Progress), `to_close` (To Close), `done` (Done), `cancel` (Cancelled)
- `reservation_state` **(selection)** — MO Readiness 🔒 readonly
  > Manufacturing readiness for this MO, as per bill of material configuration:             * Ready: The material is available to start the production.             * Waiting: The material is not available to start the production. 
  > Opções: `confirmed` (Waiting), `assigned` (Ready), `waiting` (Waiting Another Operation)
- `product_description_variants` **(char)** — Custom Description
- `propagate_cancel` **(boolean)** — Propagate cancel and split
  > If checked, when the previous move of the move (which was generated by a next procurement) is cancelled or split, the move generated by this move will too
- `is_locked` **(boolean)** — Is Locked
- `is_planned` **(boolean)** — Its Operations are Planned 🔒 readonly
- `allow_workorder_dependencies` **(boolean)** — Allow Work Order Dependencies
- `is_outdated_bom` **(boolean)** — Outdated BoM
  > The BoM has been updated since creation of the MO
- `create_date` **(datetime)** — Created on 🔒 readonly
- `write_date` **(datetime)** — Last Updated on 🔒 readonly
- `extra_cost` **(float)** — Extra Unit Cost
- `subcontracting_has_been_recorded` **(boolean)** — Has been recorded?
- `log_note` **(text)** — Log note
